# Changes

Propose changes on a branch and open a pull request against `main`. Keep changes focused and include a short description plus relevant test results; add screenshots for interface changes.

For non-admin contributors, `main` requires one approving review from a reviewer with write access. The latest push must be approved by someone other than its author, new commits dismiss stale approvals, and review conversations must be resolved. Force pushes and deletion of `main` are disabled by the branch rule.

The public repository accepts proposals, but public access does not grant write or merge access. Only explicitly invited collaborators can review with approval authority. The repository owner retains the admin exception and can explicitly merge their own pull requests without a separate reviewer or bot identity. Use pull requests for owner changes too, so the changes remain reviewable.

See the [code guide](docs/CODEBASE.md) for formatting and test commands. Preserve existing place IDs and saved-data compatibility. New place stories and images need source evidence and reviewed reuse rights.
