# Changes

Propose changes on a branch and open a pull request against `main`. Keep changes focused and include a short description plus relevant test results; add screenshots for interface changes.

`main` requires one approving review from a reviewer with write access. The latest push must be approved by someone other than its author, new commits dismiss stale approvals, and review conversations must be resolved. These protections apply to admins. Force pushes and deletion of `main` are blocked.

The public repository accepts proposals, but public access does not grant write or merge access. Only explicitly invited collaborators can review with approval authority. GitHub does not let pull-request authors approve their own work; an owner-authored pull request needs another trusted reviewer.

See the [code guide](docs/CODEBASE.md) for formatting and test commands. Preserve existing place IDs and saved-data compatibility. New place stories and images need source evidence and reviewed reuse rights.
